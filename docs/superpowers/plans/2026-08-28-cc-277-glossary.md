# CC-277 Glossary Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make glossary terms first-class Corpus content and safely expose them to Leitner.

**Architecture:** Corpus owns terms and CRUD. `app/bridges/leitner_corpus` is conditionally loaded by Leitner only when Corpus exists, returning visible terms for secure front-node tokenisation.

**Tech Stack:** AdonisJS 6, Lucid/PostgreSQL, Inertia 2, Vue 3, Vitest, Japa.

**Spec:** `docs/superpowers/specs/2026-08-28-cc-277-glossary-design.md`

## Global Constraints

- `> notion:` is removed after an additive, lossless migration.
- Terms default private; only their owner or an admin writes them.
- No inter-module SQL when either module is disabled.
- Front rendering remains server-tokenised and rendered as Vue nodes, never reconstructed HTML.
- Exchange format v6 must preserve terms and report unavailable Corpus content.
